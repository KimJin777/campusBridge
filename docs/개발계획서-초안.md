**경남대 캠퍼스 AI 도우미 — 기존 업무를 바꾸지 않는 학생 행정 안내 Agent**

## 과제소개 (1페이지 이내)

### 목적

경남대학교의 학칙·규정, 학사·장학 공지, 학사일정, 캠퍼스 시설 정보는 규정관리시스템과
홈페이지 여러 메뉴에 흩어져 있다. 학생은 필요한 정보를 찾지 못해 행정부서에 전화·방문하고,
부서는 같은 질문에 반복 응대한다. 본 과제는 **학교의 기존 시스템과 업무 방식을 전혀 바꾸지 않고**,
이미 공개된 정보만으로 학생의 질문을 처리하는 AI Agent를 개발한다.

### 핵심 원칙: 기존 업무 무변경 (Zero-Touch)

> **학교 구성원 모두가 지금 하던 일을 지금처럼 하고, 시스템이 그 결과물을 연결해 학생의 편리성만 높인다.**

- **학교 시스템 무변경**: 학사정보시스템·홈페이지에 연동 개발이나 API 요청을 하지 않는다.
  공개된 규정 원문(HWP)·게시판 RSS·공개 웹페이지만 읽는다.
- **담당자 추가 업무 없음**: 교직원이 챗봇용 자료를 따로 작성·등록하지 않는다.
  부서는 평소처럼 규정을 개정하고 공지를 올리면, Agent가 이를 자동으로 감지해 반영한다.
- **책임 경계 유지**: Agent는 원문 근거를 인용해 안내만 하고, 최종 확인과 처리는
  기존 담당 부서로 연결한다. 행정 결정 권한을 대신하지 않는다.

### 개발 내용

1. **근거 인용형 규정 안내**: 학칙·학사 규정을 조(條) 단위로 색인하여, 답변마다
   "학칙 제○조 (개정 ○○, 소관 ○○팀)"와 원문 링크를 함께 제시. 근거가 없으면 답하지 않고 담당 부서를 안내.
2. **실시간 정보 도구 호출**: 질문 의도에 따라 Agent가 학사·장학공지(RSS), 학사일정, 식단 등
   최신 정보를 직접 조회하여 규정과 결합.
3. **개인 조건 맞춤 절차 체크리스트**: 학년·학적·장학 수혜 여부 등을 되물어,
   해당 학생에게 맞는 절차·기한·서류·주의사항(예: 휴학 시 장학금 반환)을 체크리스트로 생성.
4. **담당 부서 위치 안내**: 규정의 소관부서 → 건물·층 → 지도 링크까지 연결.
5. **미응답 질문 대시보드**: 답하지 못한 질문을 모아 "학생들이 모르는 정보"를 부서에 제공
   (보기만 하면 되는 참고자료로, 부서 업무를 늘리지 않음).

### 기대효과

- 학생: 여러 사이트를 뒤지지 않고 한 곳에서, 근거와 함께, 본인 상황에 맞는 답을 얻음.
- 부서: 반복 문의 감소. 도입 비용·업무 변경 부담이 없어 즉시 운영 가능.
- 학교: 학생 궁금증 데이터를 통해 안내가 부족한 영역을 파악.
- **확장(지역 문제)**: 예비입학생(도내 고교생)용 입시·학과 안내로 확장하면,
  지방대 신입생 모집 위기와 지역 인재 유출 문제에 대응하는 공공 안내 채널이 됨.
  같은 무변경 방식으로 도내 다른 대학에도 이식할 수 있음.

## 개발 계획 (2페이지 이내)

### 개발 방법

**데이터 계층 (기존 공개 자료만 사용)**

| 소스 | 수집 방식 | 용도 |
|---|---|---|
| 규정관리시스템 (yz.kyungnam.ac.kr/rule) 제2편 학칙·제3편 학사행정 등 학생 관련 규정 | HWP → 텍스트 변환, 조 단위 청킹, 개정차수·소관부서 메타데이터 | 근거 인용 답변 |
| 학사공지·장학공지·일반공지 | 게시판 RSS 2.0 | 최신 공지 조회 도구 |
| 학사일정, 장학안내, 기숙사, 주간식단 | 공개 페이지 수집(캐싱, 요청 간격 준수) | 일정·생활 정보 도구 |
| 건물·부서 위치표 | 캠퍼스투어·조직도 기반 1회 구축 (건물·층·부서·좌표) | 길 안내 도구 |

- 규정 개정 감지: 규정 파일명의 버전 번호를 주기적으로 비교해 변경분만 재색인.

**Agent 계층**

- Goal: 학생의 질문을 "근거 있는 답 + 실행 가능한 다음 행동"으로 해결.
- Tools: `search_rules`, `get_notices`, `get_academic_calendar`, `get_menu`, `find_location`
- Workflow: 의도 파악 → (필요 시) 개인 조건 되묻기 → 도구 선택·호출 → 근거 검증
  (인용 없는 문장 제거) → 체크리스트·위치·원문 링크로 응답.
- Memory/Feedback: 대화 중 학생 조건 기억, 답변 유용성 피드백·미응답 질문 기록.

**서비스 계층**: 웹 챗 UI (모바일 우선), 관리자용 미응답 질문 대시보드.

| 구분 | As-Is | To-Be |
|---|---|---|

### 기타

- 공개 정보만 사용하고 개인정보(학번·성적 등)는 수집·저장하지 않음. 개인 조건은 대화 중에만 사용.
- 학교 서버 부담 최소화: RSS 우선, 수집 결과 캐싱, 요청 간격 준수.
- 향후 계획: 예비입학생용 입시·학과 안내 확장, 공지 첨부파일(HWP/PDF) 분석, 도내 타 대학 이식.
