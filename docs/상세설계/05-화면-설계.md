# 05. 화면 설계

순수 HTML/CSS/JS(빌드 도구 없음), 모바일 우선(기준 폭 360px), 데스크톱은 최대 폭 720px 가운데 정렬.

## 1. 학생 챗 화면 (`/`)

### 1-1. 구성

```
┌─────────────────────────────────┐
│ 캠퍼스 브릿지        [새 대화 시작] │  ← 헤더
├─────────────────────────────────┤
│ (첫 화면) 인사 문구               │
│ [휴학 신청 절차] [성적 경고·재수강] │  ← 추천 질문 칩
│ [오늘 학식 메뉴] [○○팀 어디?]     │
│ [범위 밖 예시]                    │
│                                   │
│ 👤 휴학하려고 하는데요             │  ← 학생 말풍선
│ 🤖 ▸ 판단 과정 (접힘/펼침)         │  ← 타임라인
│    ✓ 질문 의도 분석               │
│    ✓ 학칙 검색 (3건)              │
│    ✓ 학사공지 확인                │
│    ✓ 근거 검증 통과               │
│   [근거 카드] [근거 카드]          │  ← 가로 스크롤
│   답변 문장¹ 답변 문장²            │  ← 인용 번호
│   ☐ 체크리스트 1 ☐ 2 ☐ 3          │

│   👍 👎                            │
├─────────────────────────────────┤
```

### 1-2. 상태와 이벤트 처리 (`app.js`)

| 상태 | 설명 |
|---|---|
| `threadId` | `localStorage` 보관(접근 실패 시 메모리). [새 대화 시작] 시 재발급 + `track(new_thread)`(turn_id 없음) |
| `requestId` | 메시지 전송마다 새 UUID. **[다시 시도]는 같은 `requestId`로 재전송**(서버가 완료분을 재전송하거나 이어서 처리 — 04 문서 2-1) |
| `busy` | 스트림 수신 중 true → 입력·칩 비활성 |
| `currentTurn` | 말풍선 DOM, 타임라인, 카드 목록, turn_id |

| SSE 이벤트 | 처리 |
|---|---|
| `meta` | `schema_version` 확인(다르면 "새로고침이 필요합니다" 안내), `turn_id` 기록, `replay`면 타임라인 생략 |
| `status` | 타임라인에 단계 추가(진행 중 ⏳ → 다음 이벤트 오면 ✓). `ok=false`면 "조회 실패", `stale=true`면 "마지막 확인 정보" 표시. `corrections`가 있으면 "'휴악'을 '휴학'으로 이해했습니다" 한 줄 |
| `evidence` | **검색 후보** 카드 추가(흐린 스타일, 중복 id 무시) |
| `ask` | 질문 말풍선 + 선택 칩(`choices`) 표시. 칩 선택 시 "2학년, 장학금 예" 문장을 만들어 `/api/chat` 전송 |
| `answer` | 문장 렌더링(인용 번호 → 해당 카드), 체크리스트, 다음 행동, 안전 안내(`notice`), 담당 부서, `as_of` 있으면 "○월 ○일 ○시 기준". **`cited`에 든 카드만 "사용된 근거"로 강조하고 나머지 후보 카드는 접는다** — 검색 후보를 답변 근거로 오해하지 않게 |
| `fallback` | 안내 문구 + 담당 부서 |
| `done` | 👍/👎 활성화, `busy=false`, 응답시간 표시(개발 모드만), 스크린리더용으로 답변 영역에 포커스 이동 |
| `error` | 서버 오류 말풍선 + [다시 시도](같은 `requestId`) |

- SSE는 `fetch` + `ReadableStream`으로 수신(POST 필요 — `EventSource`는 GET만 지원).
- **청크 경계 버퍼링**(`frontend/sse.js`): 네트워크 청크가 이벤트 중간에서 잘려 들어오므로 버퍼에 누적하고 빈 줄(연속 개행 두 번) 단위로 완성된 이벤트만 파싱한다. 남은 조각은 다음 청크와 합친다. 1일차에 먼저 만들고 단위 테스트(잘린 청크 입력) 추가.
- **렌더링은 `textContent`로만** 한다. 답변은 구조화 JSON이므로 마크다운·HTML 렌더러(`marked.js` 등)를 쓰지 않는다(모델 출력의 HTML 주입 방지).
- **연결 끊김**: 스트림이 중간에 끊기면 이미 받은 타임라인·근거 카드는 그대로 두고 "연결이 끊겼습니다 [다시 시도]"를 표시한다(모바일에서 앱 전환 후 복귀 등). **네트워크 끊김과 서버 오류(`error` 이벤트) 문구를 구분**한다.
- **409(`THREAD_BUSY`)**: 오류 말풍선 대신 "이전 질문을 처리하고 있습니다" 짧은 안내.
- 근거 카드 클릭 → 원문 링크 새 탭(`rel="noopener noreferrer"`) + `track(source_click, card_state)`.
- 원문 링크는 **`https:` 프로토콜 + 허용 도메인**(`kyungnam.ac.kr` 하위)일 때만 활성화.
- **모든 외부 텍스트**(답변·공지 제목·부서명·질문 에코)는 `textContent`로 넣는다. `innerHTML` 사용 금지.
- 👍/👎는 한 번 누르면 "저장됨"으로 바뀌고 중복 전송하지 않는다(다시 누르면 변경만 전송).
- 접근성: 버튼 `aria-label`, 타임라인은 `aria-live="polite"`.

### 1-3. 추천 질문 칩 (`GET /api/suggestions`)

| 칩 | 시연 기능 |
|---|---|
| 휴학 신청 절차 알려 주세요 | 되묻기 → 체크리스트 |
| 성적 경고 기준과 재수강 규정 | 규정 근거 인용 |
| 오늘 학생식당 메뉴 | 실시간 도구 |
| 장학금 신청 언제까지예요? | 규정 + 장학공지 |
| (부서·연구소명) 어디 있어요? | 텍스트 위치 + 원문 링크(지도 없음) |
| 범위 밖 예시(1개) | fallback |

서버 설정으로 관리해 시연 전 문구를 바꿀 수 있게 한다. **칩을 누르면 입력창을 거치지 않고 바로 전송**한다(원클릭 시연).

## 2. 처리방침 페이지 (`/privacy`)

- 수집 항목: 질문 내용(개인정보 패턴 마스킹 후), 응답 결과 유형, 피드백, 클릭 이벤트. 로그인·쿠키 없음
- 브라우저 저장: 대화를 이어 가기 위한 **무작위 대화 ID를 `localStorage`에 저장**(개인 식별 정보 아님, [새 대화 시작]으로 교체)
- 목적: 서비스 개선·미응답 질문 통계
- 보존: 90일 후 자동 삭제(대화 상태는 24시간)
- 문의처: 운영팀 연락처

## 3. 관리자 페이지 (`/admin`) — 운영자용 (#450~#457)

- **대상**: 프로젝트 운영자(팀·산학협력단). 학교 행정부서에는 새 업무가 없다. 정상 상태에서는 자동으로 돌고, **예외 때만** 조작한다.
- **로그인**: Google 로그인(허용 이메일). 관리자 키 입력 방식은 폐기.

| 탭 | 내용 | 우선 |
|---|---|---|
| **데이터 출처** | 출처별 상태·마지막 수집·다음 예정·문서 수, **주기 preset 변경, 일시정지/재개**, [변경분 다시 수집] 버튼 | **Core** |
| **수집 실행** | 실행 이력, 진행 배너(`phase`, `processed/total`, 추가/변경/거부 건수), 실패 원인(안전한 요약만) | **Core** |
| **긴급 회수** | 문서·조문 검색 제외(즉시), 사유 입력 필수 | **Core** |
| **감사 로그** | 누가·언제·무엇을·왜 | **Core** |
| 교내 문서 | 업로드 → 미리보기(분할 결과) → 승인 근거 확인 → 게시 / 거부 / 게시 중단 | P1 |
| 장소 표 | 건물·부서·연구소 위치 수기 등록·수정·검수(원문 URL·확인일 필수) | P1 |
| 검수 대기함 | 거부된 규정(조 개수 급감 등), guide 선택자 깨짐, 부서 디렉터리·장소 표 추출 결과(`pending`), 출처 충돌 답변 | P1 |
| 미응답 질문·부정 피드백 | 빈도순(범위 밖 제외) — 참고자료 | P1 |
| 통계 | 요약 타일·일자별 추이(평균·p50·p95) | P1 |
| glossary | 적용 중인 사전 읽기 전용 | P2 |

- 버튼은 모두 확인 대화상자, 위험 작업(purge)은 사유 입력 + 2단계 확인.
- 부서용 문구: "이 화면은 운영자용입니다. 학교 부서의 별도 조치는 필요하지 않습니다."
