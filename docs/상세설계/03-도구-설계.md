# 03. 도구 설계

Agent가 호출하는 도구 5종. 모두 `tools/` 아래 LangChain `@tool`로 정의하고, **반환값은 모두 `ToolResult` 하나로 통일**한다.

```python
class ToolResult(BaseModel):          # backend/domain/evidence.py
    ok: bool
    items: list[Evidence] = []
    error_code: str | None = None     # UPSTREAM_TIMEOUT, UPSTREAM_ERROR, PARSE_ERROR, NOT_FOUND, BAD_INPUT
    message: str | None = None        # 사용자 안내용 짧은 문구(예: "게시된 식단이 없습니다")
    as_of: datetime | None = None     # 데이터 확인 시각
    stale: bool = False               # 마지막 정상 캐시를 썼는가
    age_seconds: int | None = None
    missing_evidence_needs: list[str] = []   # 근거를 못 찾은 사실 종류(#447 P0-3)
    missing_source_kinds: list[str] = []     # 실패·0건인 출처 종류(예: guide timeout) — 부분 근거 판별용
```

| 상황 | 반환 |
|---|---|
| 성공 | `ok=True, items=[…]` |
| 정상적인 빈 결과(식단 없음 등) | `ok=True, items=[], message="…"` |
| 장애 | `ok=False, items=[], error_code="UPSTREAM_TIMEOUT"` |
| 마지막 정상 캐시로 대체 | `ok=True, stale=True, as_of=…, age_seconds=…` |

Agent는 `ok=False`를 evidence로 만들지 않고 타임라인 상태에만 반영한다(02 문서 `run_tools`).

## 공통

- 타임아웃: 외부 HTTP 5초, Vertex AI Search 5초 — 단, **턴 전체 마감(25초)의 남은 시간을 넘지 않는다**(07 문서 5절)
- 재시도: 공통 래퍼(07 문서) — 429·5xx·타임아웃만 재시도
- URL 제한: `ALLOWED_HOSTS = {"yz.kyungnam.ac.kr", "www.kyungnam.ac.kr"}` 외 요청 거부. 도구 인자로 URL을 받지 않는다(게시판·날짜 같은 **열거형·값만** 받음 → SSRF 차단). **리다이렉트 후 최종 URL도 허용 목록으로 재검사**하고 `https:`만 허용
- **입력 상한**: `query`·`keyword` ≤ 100자, `top_k` ≤ 8, `days` ≤ 180, 날짜 범위 ≤ 120일, `name` ≤ 30자. 초과 시 잘라서 사용(`BAD_INPUT`은 형식 오류일 때만)
- HTML 정제: 스크립트·스타일·이벤트 속성·숨김 요소 제거 후 텍스트 추출
- 실패 반환: 예외를 던지지 않고 `ToolResult(ok=False, …)`. 표가 비었으면 `ok=True, items=[], message="현재 게시된 정보가 없습니다"`, 파싱 실패면 `ok=False, error_code="PARSE_ERROR"` — 두 경우 모두 화면에 **원문 페이지 링크**를 안내(링크는 설정값에서, 모델이 만들지 않음)
- **비동기 규칙**: HTTP는 `httpx.AsyncClient`로 받고, 동기 라이브러리(`feedparser`, BeautifulSoup, Vertex AI Search 동기 SDK)는 **받은 문자열만 처리**하거나 `asyncio.to_thread`로 감싼다. 이벤트 루프에서 네트워크 대기 금지
- 인코딩: 응답 charset이 없거나 깨지면 EUC-KR/CP949 감지 후 디코딩

## 1. `search_academic_knowledge(query: str, kinds: list[Literal["rule","guide"]], original_query: str | None = None, top_k: int = 5) -> ToolResult`

(구 `search_rules`를 일반화 — #419·#422·#426 합의)

| 항목 | 내용 |
|---|---|
| 설명(모델용) | "학칙·학사 규정과 학사안내 페이지에서 근거를 찾는다. 규정·절차 질문이면 가장 먼저 호출" |
| 입력 | `query`: classify의 `normalized_query` 기반 `search_query` / `kinds`: **서버가 계산해 항상 명시**(아래 매핑). 빈 배열·알 수 없는 값은 `BAD_INPUT` / `original_query`: 보정 전 질의(조건부 폴백용) |
| 처리 | Vertex AI Search(필터 `access="public"`, `source_kind ∈ kinds`) → **서버 denylist(`disabled_document_ids`)로 결과를 다시 거른 뒤**(긴급 회수 즉시 반영 — Vertex 비활성화 반영 지연 대비, #456) → 상위 `top_k` |
| **조건부 원문 폴백**(#427) | 보정 신뢰도가 경계값이거나 결과가 최소 점수·개수 기준 미달일 때만, **같은 도구 호출 안에서** `original_query`로 한 번 더 검색. 두 결과가 크게 다르면 `ToolResult.message`로 알리고 `needs_review` 후보로 표시. 고신뢰 보정이면 폴백 없음(지연·비용 절약) |
| 반환 | 조문: `Evidence(kind="article", id=article_id, …, meta={source_kind:"rule", department, dept_id, revision_date, revision_no, rule_level, has_table})` / 안내: `Evidence(kind="guide", id="guide:{page_id}:{section}", title="{페이지명} — {소제목}", text=본문, url=페이지, meta={source_kind:"guide", department, phone, page_modified, fetched_at})` |
| 로깅 | 검색어, `evidence_needs → kinds`, 폴백 여부, 반환 id 순서(`turns.retrieved_ids` — Recall@5 재료) |
| 대체 | 로컬 하이브리드 검색으로의 전환은 **런타임 자동 전환이 아니라, 사용자가 승인하는 프로젝트 결정**이다(구현전략 3-3). 전환해도 같은 시그니처 유지 |

**`evidence_needs → kinds` 서버 매핑**(결정적, `agent/needs.py`)

| classify의 `evidence_needs` | 검색 `kinds` | 추가로 부르는 도구 |
|---|---|---|
| `eligibility_or_limit`(요건·한도) | `[rule]` | — |
| `current_deadline`(이번 학기 날짜·마감) | `[rule]`(일반 기간 범위 확인용) | `get_academic_calendar`, `get_notices` |
| `procedure_and_contact`(절차·서류·창구) | `[guide, rule]` | — (담당 부서는 인용 근거의 `dept_id`로 서버가 **부서 디렉터리**에서 붙임 — `department`는 검색 종류가 아님) |
| `menu` | — | `get_menu` |
| `location` | — | `find_campus_location` |


- 한 질문에 여러 `evidence_needs`가 있어도 Agent 관점의 **도구 호출은 1회**다. 다만 전역 `top_k` 하나로 받으면 규정이 상위를 독점해 guide가 0건이 될 수 있으므로(#432), **도구 내부에서 필요한 kind별로 병렬 1회씩 검색**하고 `evidence_need`별 최소 1건을 보장해 병합한다(중복 제거, 전체 반환 상한 유지). 특정 need의 근거가 0건이면 `ToolResult`에 `missing_evidence_needs[]`를 명시한다.
  - **부분 결과 계약**(#437): kind별 요청 중 하나가 timeout·429여도 **다른 kind 결과는 버리지 않고** 반환하며 실패한 쪽은 `missing_evidence_needs`에 적는다. 429에 재시도로 지연을 늘리지 않는다. 전체는 도구 timeout과 T+5 체크포인트 안에서 병합한다
  - 지연 기대값은 문서에 적지 않는다 — 1일차 D14 실측(단일 kind / 2-kind fan-out / 원문 폴백의 p50·p95·요청 수·비용)으로 대체
- 담당 부서·연락처는 검색 kind가 아니지만 **구조화된 근거 원천**이다(#432): 인용 근거의 `dept_id`로 검수된 부서 디렉터리를 서버가 조회해 `ToolResult`로 남기고, 부서 페이지 URL·스냅샷 확인일을 함께 반환한다. 모델이 전화번호·위치를 생성하거나 guide 본문에서 복사하지 않는다.
- 요약·답변 생성 기능은 쓰지 않고 **원문만** 받는다.
- 부칙(`kind="add"`)은 질문에 시행일·경과 관련 표현이 있을 때만 포함.

## 2. `get_notices(board: Literal["academic","scholarship","general"], keyword: str = "", days: int = 30) -> ToolResult`

| 항목 | 내용 |
|---|---|
| 소스 | 학사공지 `/bbs/ko/1398/rssList.do?row=50`, 장학공지 `/bbs/ko/1407/rssList.do?row=50`, 일반공지 `/bbs/ko/1408/rssList.do?row=50`(GPT5 #422 확인). 순서는 DOM이 아니라 `pubDate` 기준(고정 공지를 최신으로 오인 금지). `description`이 빈 글은 제목만 쓰고 필요할 때만 상세 페이지 조회. 장학공지는 마감일이 RSS에 없을 수 있어 상세 페이지 보강 |
| 처리 | `httpx.AsyncClient`로 XML 수신 → `feedparser.parse(문자열)` → 최근 `days`일 → `keyword`(공백 분리, 제목·요약 포함 여부) 필터 → 최신순 최대 5건 |
| 날짜 | `published_parsed`가 없으면 대체 파서로 `2026.09.28`, `2026-09-28 14:00` 등 비표준 표기 처리. 시간대 표기가 없으면 **KST로 간주**. 그래도 실패하면 `published_at=null`로 두고 기간 필터에서 제외하지 않되 목록 끝에 둠 |
| 반환 | `Evidence(kind="notice", id="notice:{board}:{guid}", title=제목, text="{제목}\n{게시일}\n{요약}", url=링크, meta={published_at, as_of})` |
| 캐시 | 게시판별 30분, 실패 시 마지막 정상값 + `as_of` |

## 4. `get_menu(day: date | None = None) -> ToolResult`

| 항목 | 내용 |
|---|---|
| 소스 | 단체식단 `https://www.kyungnam.ac.kr/ko/4454/subview.do`, 푸드코트 `/ko/8978/subview.do` |
| 형식(확인됨, #422·#424) | **HTML 표가 아니다.** "[단체식단] 9/28~10/2 주간메뉴" 같은 **게시물 + 첨부 PDF**(`fileDownload.do`, 뷰어 `viewPlus.do`) |
| 처리 | 목록에서 요청 날짜를 포함하는 게시물(제목의 기간) → 첨부 PDF 다운로드 → **텍스트 레이어가 있으면** 식당·요일·끼니 구조로 파싱 |
| 이미지형 PDF | **OCR 하지 않는다.** `ToolResult(ok=True, items=[원문 PDF 링크 안내 항목], message="식단은 원문에서 확인해 주세요")` |
| 반환 | 파싱 성공: `Evidence(kind="menu", id="menu:{date}", title="{date} 식단", text=식당·끼니별 메뉴, url=게시물, meta={as_of, record_id})` |
| 캐시 | `record_id + content_hash` 기준 주간 캐시 |
| 비고 | 주말·방학 등 해당 기간 게시물 없음 → `ok=True, items=[], message` / 1일차 스파이크로 텍스트형 여부 확정 |

## 5. `find_campus_location(query: str) -> ToolResult` — 결정적 조회 (#481·#486·#489)

| 항목 | 내용 |
|---|---|
| 소스 | `data/places.csv`(01 §4-1) — **`status=verified` 행만** |
| 처리 | 정식 이름 정확 일치 → 별칭 일치 → 부분 일치(편집거리 ≤ 1). 벡터 검색·LLM 생성 없음 |
| 반환 | `Evidence(kind="place", id="place:{place_id}", title=name, text="{name}: {상위 건물 name} {floor}층 {room}호" 또는 raw_location, url=source_url, meta={kind, parent_place_id, snapshot_at})` |
| 모호함 | 후보가 2개 이상이면 **임의로 고르지 않고** 후보 목록(`message="여러 장소가 있습니다"`) |
| 없음 | `ok=True, items=[], message` → 담당 부서 연락처 안내로 대체 |
| 범위 밖 | 좌표·지도 링크 없음, 개별 연구실·교직원 좌석 없음 |

## 6. 도구 선택 가이드 (act 프롬프트에 포함)

| 질문 유형 | 호출 순서(예) |
|---|---|
| 규정 해석("F 두 번이면 경고?") | `search_academic_knowledge(kinds=[rule])` |
| 절차("이번 학기 휴학 언제까지, 어떻게?") | `search_academic_knowledge(kinds=[guide, rule])` + `get_notices(academic, "휴학")` + `get_academic_calendar` (병렬) |
| 장학("장학금 신청 언제?") | `search_academic_knowledge(kinds=[rule])` + `get_notices(scholarship)` |
| 일정("중간고사 언제?") | `get_academic_calendar` |
| 식단 | `get_menu` |
| 위치("학사지원팀 어디?", "○○연구소 어디?") | `find_campus_location` |
