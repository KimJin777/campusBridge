# 08. 테스트 설계

`pytest` + `pytest-asyncio`. 외부 호출(Gemini·Vertex·Firestore·학교 사이트)은 **목(mock)** 으로 대체해 네트워크 없이 돈다. 통합 점검은 배포 후 `smoke.sh`(07 문서)와 평가 실행기(06 문서)가 맡는다.

- **목은 우리 인터페이스 경계에서** 만든다: 그래프 테스트는 도구가 **`ToolResult`**(03 문서)를 돌려주도록 대체한다(`conftest.py`의 `make_evidence(article_id, text, **meta)`, `make_tool_result(ok, items, stale=False, error_code=None)` 팩토리). Discovery Engine SDK의 중첩 응답 구조는 **SDK → Evidence 변환 어댑터 테스트 한 곳**에서만 다룬다.
- **이 문서는 구현 계약의 최종 판정 기준이다.** 01~07 문서가 바뀌면 이 문서의 기대값도 같은 개정에서 함께 고친다(#406 합의).

### 1-3. Agent (`tests/test_graph.py`) — 모델은 목 응답

| 테스트 | 기대 |
|---|---|
| 범위 밖 분류 | fallback 경로, `fallback_reason="out_of_scope"`, **`unanswered` upsert 호출 안 함**(통계에만 기록) |
| 근거 없음 | `fallback_reason="no_evidence"`, `unanswered` upsert 호출(완료 시 1회) |
| 조건 부족 | `ask_user` → `pending_question` 저장, outcome=ask |
| guide 근거 | `search_academic_knowledge`의 guide 결과가 `Evidence(kind="guide")`·`ToolResult` 검증을 통과하고 인용 카드로 전달됨 |
| kind fan-out | rule이 고득점을 독점해도 guide 최소 1건 유지 / guide timeout → rule 결과 + `missing_evidence_needs` / 두 kind의 중복 문서 1건 병합 / 전체 상한·입력 kind 순서가 바뀌어도 결과 계약 유지 |
| 입력 정규화 | 분해 자모(NFD) 입력 → NFC 합성 / 초성만 입력 "ㅎㅎ" → 추정 복원 없이 확인 질문 / glossary 약칭 "학경" → 학사경고 |
| guide 정제 | 안내 페이지 저장본 → 탭·메뉴·만족도 문구가 본문에 없음 / **"신청 바로가기"·"서식 다운로드"는 `links[]`로 보존** / 최소 본문·필수 제목 미달 → 색인 거부·기존본 유지(스냅샷) |
| evidence_needs 매핑 | "이번 학기 휴학 언제까지, 어떻게?" → needs {current_deadline, procedure_and_contact} → 검색 kinds [guide, rule] 한 번 + 일정·공지 도구 / 빈·미지 kinds → BAD_INPUT |
| 출처 판정 | 공지(늦게 게시·"연장" 표지)와 학사일정 날짜 다름 → 공지 우선 / 표지 없이 다름 → 둘 다 표시 + needs_review / 규정 일반 기간 안의 실제 날짜 → 충돌 아님 / 요건 숫자 규정≠안내 → 규정 기준 + 템플릿 문장 |
| 오타 보정 | "복학 언제 신청해" ≈ "…신청해요" 같은 의도 / "휴악 신청" → 휴학 보정·타임라인 표시 / 휴학→퇴학 보정 시도 → 서버 거부·확인 질문 / "2026-1"↔"2026-2" 자동 수정 금지 / 저신뢰 보정 → 도구 내 원문 폴백 1회 / 오타 확인 + 조건 되묻기 → 질문 1개로 합침 / 증거 본문은 보정 안 됨 |
| classify 통합 | classify 1회 호출로 `intent`·`search_query`가 함께 나오고 별도 확장 호출이 없음 |
| 모델 경계 마스킹 | 학번·전화·이메일이 든 질문 → 모델 목이 받은 입력에 원문 패턴이 없음(`query_for_model`) |
| 위험 토큰 불일치 표시 | 문장 "할 수 없다" vs 인용 "할 수 있다", 문장에 없는 "다만" 예외 누락 등 → 문장은 유지, `needs_review`에 기록 |
| 조건 답 후 재개 | 다음 턴에서 `original_query_masked`로 이어 처리, `profile` 병합 |
| 두 번째 되묻기 방지 | 이미 물었으면 다시 묻지 않음 |
| 도구 상한 | 호출 건수 4건 도달 시 compose로 진행, 초과분 미실행 |
| 구조화 출력 실패 | 1회 재시도 후 fallback |
| 도구 실패 | 다른 근거로 진행 또는 fallback, 예외 전파 없음 |

| fallback | 범위 밖 질문은 `unanswered`에 안 들어감, `no_evidence`만 누적 | 통과 |
| 도구 | `ToolResult` 계약(성공·빈 결과·장애·stale) / 리다이렉트된 외부 도메인 차단 / stale 공지로 마감일 확정 답변 금지 / 입력 상한 | 통과 |
| 마감 | 도구 지연 목으로 25초 초과 유도 → 확보한 근거로 compose 또는 `deadline` fallback | 통과 |
| UI | HTML 문자열이 텍스트로 표시되고 스크립트 미실행 / 후보 카드와 인용 카드 구분 / 같은 requestId 재시도 | 통과 |
| HWP | Job 이미지에서 `hwp5txt` 실행, 실패 시 `rejected` 경로 | 통과 |
| 피드백 | 같은 turn 재전송 시 문서 1개 유지 | 통과 |
| 분할 | 같은 날짜 부칙 2개 → ID 충돌 없음(순번) / 항 없는 긴 조 → `_c{n}` / 별표 뒤 조 머리 → 본문 복귀 / 변환 텍스트 급증 → 갱신 보류 | 통과 |
