# 캠퍼스 브릿지(campusBridge) 상세설계 종합 검토 및 리뷰

- **작성일시**: 2026-09-28
- **검토 대상 문서**: `docs/상세설계/00-개요.md` ~ `08-테스트-설계.md` (전체 9종)
- **리뷰 목적**: 8일간(9/29~10/6)의 개발 기간 동안 구현 누락 및 기술적 병목을 사전에 차단하고, 완성도를 극대화하기 위한 상세설계 정합성 및 실전 구현 검토

---

## 1. 종합 평가 (Executive Summary)

제출된 9종의 상세설계서는 **대회 신청서의 요구사항, 상위 구현전략, 선행 프로젝트(MatchProf)의 운영 노하우가 매우 높은 수준으로 일관되게 반영**되어 있습니다.

- **우수 사항**:
  - `article_id` 네임스페이스(`main` vs `add`) 분리로 부칙 조문 충돌을 원천 차단함.
  - SSE 이벤트 규격(`status`, `evidence`, `ask`, `answer`, `done`)을 통해 심사위원 평가의 핵심인 "Agent 판단 타임라인"을 명확히 구현 가능하게 설계함.
  - `verify.py`에서 LLM을 배제하고 결정적 코드(문장별 인용 ID, 인용 본문 텍스트 일치율, 숫자 검증)로 환각을 차단하는 구조가 탁월함.
  - 50문항 평가셋을 `dev(35)`와 블라인드 `final(15)`로 분리하여 데이터 오염을 방지한 설계가 인상적임.

8일이라는 초단기 일정 속에서 실제 코딩 시 맞닥뜨릴 수 있는 **세부 엣지 케이스 및 구현 병목을 예방하기 위한 문서별 세부 검토 및 보강 제안**은 다음과 같습니다.

---

## 2. 문서별 상세 검토 및 개선 제안

### [01. 데이터 설계]
1. **대학 웹서버 인코딩(EUC-KR vs UTF-8) 대응**:
   - 경남대 규정관리시스템(`yz.kyungnam.ac.kr`) 및 메인 게시판의 구형 페이지는 `EUC-KR` 또는 `CP949`로 응답할 가능성이 있습니다.
   - `httpx` 요청 시 `response.encoding = response.apparent_encoding` 또는 `chardet`을 통한 인코딩 자동 감지 폴백을 전처리 모듈에 추가 권장합니다.
2. **장·절 구조가 없는 소규모 규정 처리**:
   - '학칙'은 제1장~제13장까지 완벽히 갖추고 있으나, '지침'이나 짧은 '시행세칙'은 장·절 머리표시 없이 바로 `제1조`로 시작하는 경우가 많습니다.
   - `split_articles`에서 `chapter`와 `section`이 `None`인 상태로 안전하게 수집되도록 기본값 처리를 확실히 둡니다.
3. **`data/locations.csv` 위치표 부서명 정규화**:
   - 규정의 `department` 표기와 위치표의 `dept`가 공백이나 특수문자(`&`, `/`, `팀`, `부`) 차이로 불일치할 수 있습니다. 1일차에 규정 전체 목록의 고유 부서명 리스트(`unique_depts.json`)를 먼저 뽑아서 전지원 님께 전달하는 파이프라인을 추천합니다.

---

### [02. Agent 설계 & 03. 도구 설계]
1. **`verify.py` 숫자 검증(`NUM_PATTERN`)의 거짓 양성(False Positive) 완화**:
   - 설계된 `NUM_PATTERN`은 환각 차단에 매우 훌륭하지만, 생성된 문장이 "제1학기"인데 근거에 "1학기"로 적혀 있거나, "2회 이상" vs "최대 2회" 등 문맥상 정당한 표현이 탈락할 위험이 있습니다.
   - **보강**: "제○조", "제○항" 외에도 "제○학기", "○학년" 등 일반적인 학적 서수 표현은 숫자 엄격 검사 목록에서 정규화 후 대조하거나 화이트리스트로 제외 처리하여 정답 문장이 통째로 버려지는 사태를 방지해야 합니다.
2. **다중 도구 호출(Tool Calling) 순서 및 지연 시간 단축**:
   - `route_after_act`가 최대 4회 루프를 돌도록 되어 있습니다. Gemini가 절차 질문에서 `search_rules`와 `get_notices`를 한 번에 호출(Parallel Tool Calling)할 경우, `ToolNode`가 이를 병렬로 처리할 수 있도록 지원해야 응답시간 10초 이내를 안정적으로 충족합니다.
3. **외부 웹 크롤링 도구(`get_menu`, `get_academic_calendar`)의 Fail-safe**:
   - 학사일정이나 주간 식단 페이지는 HTML 테이블 구조가 비정형적이거나 학기 초/방학 중에 빈 테이블이 반환될 수 있습니다.
   - 표 파싱 실패 시 서버 에러(500) 대신 `items: []`와 함께 "현재 게시된 식단/일정이 없습니다(원문 링크 안내)" 형태의 안내 카드를 반환하도록 안전 캡슐화를 보장합니다.

---

### [03. API 설계 & 05. 화면 설계]
1. **SSE 연결 안정성 및 브라우저 포커스 아웃 대응**:
   - 모바일 브라우저 환경에서 사용자가 카카오톡 등을 보다가 돌아올 때 SSE 스트림이 중간에 끊길 수 있습니다.
   - 15초 `: ping` 외에도, 클라이언트(`app.js`)에서 `fetch` 에러 발생 시 현재까지 수신된 `evidence`와 `draft`를 날리지 않고 "답변을 불러오는 중 연결이 끊겼습니다. [다시 시도]" 버튼을 화면에 유지하도록 구성합니다.
2. **동시 요청 제어(`processing_until`)의 프론트 UX**:
   - 백엔드에서 409를 던질 때, 프론트엔드가 이를 일반 에러로 띄우지 않고 "이전 질문을 처리하고 있습니다. 잠시만 기다려 주세요."라는 토스트 팝업으로 부드럽게 안내합니다.
3. **추천 질문 칩 클릭 시 즉시 전송 UX**:
   - 첫 화면의 `[휴학 신청 절차]`, `[오늘 학식 메뉴]` 칩을 누르면 입력창에 텍스트가 들어가고 자동으로 전송(`handleSend`)되도록 구현하여 3분 시연 영상 녹화 시 원클릭 데모가 가능하도록 합니다.

---

### [06. 평가 설계 & 08. 테스트 설계]
1. **LLM 채점기(Judge)의 결정론적 채점 보장**:
   - `eval/run_eval.py`에서 `key_facts` 포함 여부를 LLM으로 채점할 때 `temperature=0.0` 설정과 함께 JSON 모드(Structured Outputs)를 사용하여 `{"fact": "...", "passed": true/false, "reason": "..."}`로 받아야 채점 결과의 재현성이 보장됩니다.
2. **1일차 오프라인 단위 테스트용 샘플 픽스처 신속 확보**:
   - 1일차 오전에 네트워크나 GCP 설정에 시간이 걸리더라도 로컬에서 `pytest`를 돌릴 수 있도록, 경남대 학칙 샘플 텍스트 2~3편을 `tests/fixtures/sample_rule.txt`로 즉시 저장하여 `test_split.py`와 `test_verify.py`를 먼저 통과시키는 TDD 방식이 유리합니다.

---

### [07. 인프라·배포 설계]
1. **Cloud Run 이미지 빌드 최적화 (LibreOffice 의존성)**:
   - HWP 변환용 `pyhwp`는 순수 파이썬 라이브러리라 가볍지만, 만약 폴백용 `libreoffice`를 Dockerfile에 포함하면 이미지 크기가 1GB를 넘어 빌드 및 배포 시간이 길어집니다.
   - **권장**: 웹 서비스(`campusbridge-web`) 컨테이너에는 `pyhwp`만 탑재하고, LibreOffice가 필요한 대량 전처리 작업은 로컬 개발 환경 또는 별도의 배치 잡 컨테이너(`campusbridge-ingest`)로 분리하여 웹 서비스 배포 속도를 2분 이내로 유지합니다.
2. **Vertex AI Search 리전 일치**:
   - Vertex AI Search(Discovery Engine)의 데이터 스토어 위치(`global`)와 Cloud Run 리전(`asia-northeast3` 서울) 간의 통신 지연을 감안하여 클라이언트 타임아웃을 5초 이상으로 여유 있게 잡아야 합니다.

## 4. 결론

현재 작성된 `00`~`08` 상세설계서는 실전 개발에 즉시 착수해도 문제없을 만큼 매우 탄탄합니다. 위에서 제안한 **① 숫자 정규화 예외 처리, ② 외부 파싱 안전장치(Fail-safe), ③ 컨테이너 빌드 경량화** 3가지만 코딩 시작 시 염두에 두시면, 8일간 무결점의 완성도 높은 MVP를 완성할 수 있을 것입니다.
