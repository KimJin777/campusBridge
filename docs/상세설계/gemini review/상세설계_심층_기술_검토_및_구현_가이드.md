## 1. 데이터 파이프라인 (01-데이터-설계) 심층 검토

### 🚨 [치명적] 1-1. 조문 정규식 매칭 시 첫 줄 본문 유실 방지
- **기존 설계의 의사코드**:
  ```python
  m = ^제\s*(\d+)\s*조(?:\s*의\s*(\d+))?\s*\(([^)]+)\)
  if m:
      이전 조 확정, 새 조 시작(...)
  else:
      현재 조 본문에 줄 추가
  ```
- **실제 대학 규정 데이터의 현실**:
  상당수 규정은 조 머리와 본문 첫 문장이 같은 줄에 붙어 있습니다.
  > `제1조(목적) 이 규정은 경남대학교 학칙 제○조에 따라 교무처의...`
- **문제점**: `if m:` 분기에서 줄 전체를 조 머리로만 처리하면 **조문의 핵심 첫 문장("이 규정은 경남대학교...")이 통째로 증발**합니다.
- **해결 구현 코드 가이드**:
  ```python
  m = ARTICLE_PATTERN.match(line)
  if m:
      commit_previous_article()
      start_new_article(no=m.group(1), branch=m.group(2), title=m.group(3))
      # 매칭 이후 남은 텍스트가 있다면 본문 첫 줄로 반드시 삽입
      remainder = line[m.end():].strip()
      if remainder:
          current_article.append_line(remainder)
  ```

### 🚨 [치명적] 1-2. 조 제목 내 괄호 중첩 처리 (`\(([^)]+)\)`)
- **문제점**: 규정 중 `제12조(타대학 취득학점(교환학생) 인정)`처럼 제목 내에 괄호가 포함된 경우 `[^)]+` 정규식은 `타대학 취득학점`에서 끊겨 제목이 깨지고 파싱 오류가 발생합니다.
- **해결 구현 가이드**:
  - `^제\s*(\d+)\s*조(?:\s*의\s*(\d+))?\s*\((.*?)\)(?=\s|$|[①-⑳])` 형태로 Lookahead를 사용하거나, 첫 번째 `(`부터 줄 끝 또는 본문 시작 기호 앞의 마지막 `)`까지 탐색하도록 설계해야 합니다.

### ⚠️ 1-3. `hwp5txt` 출력에서의 표(Table) 추출 특성
- pyhwp의 `hwp5txt`는 HWP 파일 내 표의 테두리(괘선) 문자를 생성하지 않고, **셀 안의 텍스트를 개행문자(`\n`)로 연속 출력**합니다.
- 따라서 설계서의 `has_table` 감지 조건 중 *"표 괘선 문자 감지"*는 동작하지 않을 가능성이 높습니다.
- **대체 감지 로직**:
  - `pyhwp`의 xml dump 레벨 메타데이터 확인 또는
  - 연속된 짧은 단어열(열 제목 형태), 탭(`\t`) 문자 비율, 혹은 금액/학점/숫자 셀 패턴이 반복 개행되는 구조를 감지하도록 보강해야 합니다.

## 2. LangGraph Agent 및 상태 관리 (02-Agent-설계) 심층 검토

### 🚨 [아키텍처] 2-1. `ToolNode`와 `TurnState["evidence"]` 동기화 어댑터
- **문제점**:
  - LangGraph의 표준 `ToolNode`는 모델의 `tool_calls`를 실행한 후 `messages` 리스트에 `ToolMessage`만 append합니다.
  - 하지만 02 설계서의 State는 `evidence: list[Evidence]`를 별도로 유지하며, 이후 `compose`와 `verify` 노드가 이 `evidence`를 기준으로 동작합니다.
- **해결 구현 가이드**:
  - 표준 `ToolNode`를 그대로 쓰면 `TurnState["evidence"]`가 비어있게 되므로, **도구 실행 결과를 `Evidence` 객체로 매핑하여 State에 넣어주는 커스텀 실행 노드** 또는 어댑터 로직을 명시해야 합니다.
  ```python
  async def run_tools_node(state: TurnState) -> dict:
      last_msg = state["messages"][-1]
      new_evidence = []
      tool_messages = []
      for tc in last_msg.tool_calls:
          tool_func = tool_map[tc["name"]]
          # 도구 반환값: list[Evidence] (dict 형태)
          raw_results = await tool_func.ainvoke(tc["args"])
          for item in raw_results:
              ev = Evidence(**item)
              new_evidence.append(ev)
          tool_messages.append(ToolMessage(content=json.dumps(raw_results, ensure_ascii=False), tool_call_id=tc["id"]))
      
      # 중복 evidence ID 제거 후 병합
      merged_ev = {e.id: e for e in (state.get("evidence", []) + new_evidence)}.values()
      return {
          "messages": tool_messages,
          "evidence": list(merged_ev),
          "tool_calls_count": state.get("tool_calls_count", 0) + 1
      }
  ```

### ⚠️ 2-2. `verify.py` 숫자 검증(`NUM_PATTERN`)의 치명적 오탐 방지
- **기존 설계**:
  `NUM_PATTERN = r"\d+(?:[.,]\d+)?\s*(?:학점|년|월|일|주|개월|학기|회|%|원|만원|시간)?"`
- **문제점**:
  단위 접미사가 `?`(선택)로 되어 있어, 단순 번호나 서수("제1항", "2단계", "1학년")의 모든 숫자 `\d+`가 매칭됩니다.
  예를 들어 학생 답변에 "1학년" 또는 "3가지 방법"이라고 썼는데 근거 본문에 "1"이라는 아라비아 숫자가 없으면(근거 본문에는 "첫째" 혹은 다른 표현인 경우) **문장 전체가 삭제되어 `verify` 통과율이 급락**하고 fallback으로 빠집니다.
- **해결 보강 규칙**:
  1. 단위가 붙지 않은 단순 아라비아 숫자는 엄격 검사에서 제외하거나 10 이상의 수치(금액, 학점, 일자 등)만 대상으로 한정.
  2. "제\d+조", "제\d+항", "제\d+호", "\d+학년", "\d+학기"는 숫자 변조 검증 정규식에서 사전 제외(`re.sub`) 처리 후 검증.

## 3. 외부 도구 및 실시간 연동 (03-도구-설계) 심층 검토

### ⚠️ 3-1. 비동기(`asyncio`) 환경에서의 동기 라이브러리 블로킹 차단
- `feedparser`(RSS 파서)와 `hwp5txt`는 **동기(Blocking) I/O 라이브러리**입니다.
- FastAPI의 비동기 이벤트 루프 내에서 `feedparser.parse(url)`를 직접 호출하면 외부 네트워크 지연 시 전체 서버 이벤트 루프가 멈춰버립니다.
- **해결 구현 가이드**:
  - `httpx.AsyncClient`로 비동기 HTTP 요청을 먼저 수행하여 XML 텍스트를 얻은 후, `feedparser.parse(xml_content)`를 메모리 내에서 실행해야 합니다.
  ```python
  async def get_notices(...):
      async with httpx.AsyncClient(timeout=5.0) as client:
          resp = await client.get(rss_url, headers=DEFAULT_HEADERS)
          # 문자열만 넘겨서 파싱 (네트워크 블로킹 방지)
          feed = feedparser.parse(resp.text)
  ```

### ⚠️ 3-2. 한국 대학 RSS 날짜 파싱 비표준 대응
- 표준 RSS는 RFC 822 포맷(`pubDate: Mon, 28 Sep 2026 09:00:00 +0900`)을 따르나, 한국 대학 솔루션은 `2026.09.28`, `2026-09-28 14:00` 등 비표준 문자열을 반환하는 경우가 매우 빈번합니다.
- `feedparser`의 `published_parsed`가 `None`이 될 경우를 대비해 정규식 fallback 날짜 파서를 `tools/notices.py`에 내장해야 합니다.

## 4. API 및 프론트엔드 연동 (04-API & 05-화면-설계) 심층 검토

### 🚨 [실전 구현] 4-1. 프론트엔드 SSE 파서(Chunk Boundary Split) 처리
- 브라우저의 기본 `EventSource`는 `GET` 요청만 지원하므로, 설계서대로 `POST /api/chat`을 수신하려면 `fetch` + `ReadableStream`을 써야 합니다.
- **주의점**: TCP 스트리밍 특성상 SSE 이벤트(`event: ...\ndata: ...\n\n`)가 네트워크 청크 단위로 **중간에 쪼개져서** 들어옵니다. (예: `ev` / `ent: status\nd` / `ata: ...`).
- 청크 경계를 버퍼링하지 않고 단순 `chunk.split('\n\n')`을 하면 JSON 파싱 에러(`SyntaxError: Unexpected end of JSON input`)로 프론트엔드가 즉시 뻗어버립니다.
- **해결 방안**:
  - 1일차에 `frontend/sse.js`에 버퍼 누적 기반의 SSE 청크 디코더(약 25줄)를 먼저 확보하고 UI 작업을 진행해야 합니다.

### ⚠️ 4-2. 마크다운 렌더링 라이브러리 명시 누락
- 화면 설계서에 답변 문장, 볼드체, 목록 표시 등이 언급되어 있으나, 빌드 도구 없는 Vanilla JS 환경에서 마크다운을 어떻게 렌더링할지 라이브러리가 명시되지 않았습니다.
- **해결 방안**: `frontend/index.html`에 경량 `marked.js` CDN 추가 명시
  ```html
  <script src="https://cdn.jsdelivr.net/npm/marked/marked.min.js"></script>
  ```

## 5. 인프라 및 배포 (07-인프라-배포-설계) 심층 검토

### 🚨 [빌드 실패 방지] 5-1. Cloud Run 컨테이너 빌드 크기 분리
- **설계 상의 함정**:
  - 07 설계서의 Cloud Run 서비스(`campusbridge-web`)와 Cloud Run Job(`campusbridge-ingest`)이 동일 Dockerfile을 공유할 경우, Job에서 필요한 `libreoffice`나 대량 전처리 패키지 때문에 웹 서비스 이미지 크기가 1.5GB 이상으로 비대해집니다.
  - 이는 배포 속도 저하(10분 이상 소요) 및 Cloud Run 인스턴스 기동 시 콜드 스타트 지연의 주원인이 됩니다.
- **해결 가이드**:
  - 웹 서비스 Dockerfile은 `python:3.12-slim` + `uv` 기반으로 순수 웹 의존성만 설치(이미지 크기 150MB 이내 유지).
  - LibreOffice는 1차 pyhwp 변환 실패 파일이 발생할 때만 로컬 변환용으로 사용하고, 운영 컨테이너에는 포함하지 않는 것을 강력히 권장합니다.
