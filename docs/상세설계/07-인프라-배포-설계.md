## 2. 서비스 계정·IAM (최소 권한)

| 계정 | 역할 |
|---|---|
| `web-sa` (서비스) | Vertex AI 사용자, Discovery Engine 뷰어(검색), Firestore 사용자, Cloud Run Job 실행자(관리자 강제 재수집용, `campusbridge-ingest`만) |
| `ingest-sa` (Job) | Discovery Engine 편집자(가져오기), Storage 객체 관리자(해당 버킷), Firestore 사용자 |
| `scheduler-sa` | Cloud Run Job 호출자 |
| Cloud Build | Run 관리자, 서비스 계정 사용자, Artifact Registry 작성자 |

- 키 파일 발급 없음. 로컬 개발은 `gcloud auth application-default login`(ADC).
- 실제 역할 ID(`roles/aiplatform.user`, `roles/discoveryengine.viewer`, `roles/datastore.user`, `roles/secretmanager.secretAccessor` 등)는 1일차에 부여하면서 이 표에 확정 기록하고, **권한 점검**(각 계정으로 모델 1회·검색 1회·Firestore 읽기/쓰기)을 수행한다.

```python
    # 재시도 대상 외 예외는 즉시 전파
    ...
```

| 호출 | 개별 제한(timeout) | 재시도 |
|---|---|---|
| Vertex AI Search | 5초 | 최대 2회 |
| 학교 사이트(RSS·페이지) | 5초 | 최대 1회 |
| Gemini(classify + search_query 생성) | 8초 | 최대 2회 |
| Gemini(compose) | 15초 | 최대 1회 |
| **턴 전체 마감** | **25초** | 남은 시간이 부족하면 재시도·추가 도구 호출 중단(02 문서) |
| 평가 실행기·수집 Job | 30초 | 최대 5회(대화 마감 없음) |

**시간 예산 2층**(#413) — `timeout`은 호출당 강제 중단값, soft budget은 "다음 선택 작업을 시작할지"의 판정값

| 층 | 값 | 역할 |
|---|---|---|
| **soft budget(정상 경로)** | 누적 체크포인트 T+2 classify · T+5 도구 · T+9 compose · T+10 verify·저장·SSE | 평균 10초 목표 관리. 체크포인트를 넘기면 다음 선택 작업(추가 도구·재시도) 생략, 실행 중인 compose는 hard deadline 안에서 마침. 보장값 아닌 측정·조정 대상 |
| **hard deadline(장애 격리)** | 25초 | 남은 시간이 부족하면 중단 → compose 또는 fallback(`deadline`) |

- 위 표의 호출별 timeout(8초·5초·15초)은 **장애 시 상한**이며 정상 경로 예산이 아니다. 순차 합(28초)이 hard deadline보다 크더라도 deadline 규칙이 우선한다.
- 1일차 실측 후 단계별 p50/p95를 기록하고 soft budget 배분을 조정한다.

- Gemini·Vertex AI Search·학교 사이트 HTTP 모두 이 래퍼 경유
- Cloud Run `timeout` 300초는 플랫폼 상한일 뿐 Agent 처리 목표가 아니다
- 매 호출 로그: 대상, 소요 시간, 재시도 횟수, 결과 코드

## 6. 빌드·배포

```
git push (main) → Cloud Build 트리거 → Docker 빌드 → Artifact Registry → Cloud Run 배포 → smoke(점검) 단계
```

- **Dockerfile 2개로 분리**
  - `Dockerfile.web`: `python:3.12-slim` + uv 잠금 파일 기반, 웹 의존성만(pyhwp·LibreOffice 없음), 비루트 사용자 — 이미지 작게 유지(배포·기동 속도)
  - `Dockerfile.ingest`: 웹 이미지 + pyhwp(수집 Job 전용)
  - **LibreOffice는 어느 이미지에도 넣지 않는다.** pyhwp 변환 실패 파일은 로컬에서 LibreOffice로 변환해 텍스트를 GCS에 올린다
- 배포 후 `scripts/smoke.sh` 실행, 실패 시 빌드 실패 처리
- 정상 상태 기록(`docs/시연-시나리오.md`): **Cloud Run 리비전 + `index_version` + Firestore 스키마 버전 + 앱 버전**을 한 줄로. 롤백: `gcloud run services update-traffic campusbridge-web --to-revisions=<리비전>=100` (색인은 기록된 버전으로 되돌림)
- Cloud Build 트리거 설정이 늦어지면 대체 경로: `gcloud builds submit --config cloudbuild.yaml` 또는 `gcloud run deploy --source .`
- GitHub는 비공개 저장소, 푸시는 2026-09-29부터

## 8. 규정 수집 Job

- **첫 전체 색인은 로컬에서** 실행한다(변환 실패 파일을 LibreOffice로 즉시 처리 가능). 검증된 TXT/JSONL만 GCS에 올리고 가져오기
- Job은 이후 **변경 감지 + `hwp5txt` 성공 파일만** 처리. 변환 실패 파일은 `rejected`로 표시하고 로컬에서 수동 변환
- 1일차 확인: Job 이미지에서 `hwp5txt` 실행 가능 여부(Python 3.12 호환), 실제 HWP 픽스처 변환
- 명령: `python -m ingest.rules all --changed-only`
- 흐름: 목록 → 매니페스트 비교 → 변경 규정만 다운로드·변환·분할·검수 → 통과분만 색인 가져오기(증분) → 매니페스트 저장(GCS)
- 검수 실패 시 해당 규정 `rejected`, 기존 색인 유지, 로그 경고
- 공지·일정·식단은 Job이 아니라 요청 시점 도구 + 캐시(03 문서)
