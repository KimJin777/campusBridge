## 1. 프론트엔드 - 백엔드 간 SSE 이벤트 프로토콜 규격

2~3일차에 백엔드와 프론트엔드가 병렬로 개발을 진행하려면, 서버-전송 이벤트(SSE) 통신 규격이 사전에 명확히 합의되어 있어야 합니다. 특히 경진대회 심사 요건인 **"입력 → 판단 → 도구 실행 → 결과"의 실시간 타임라인 노출**을 지원하는 구조입니다.

### 1-1. SSE 스트림 엔드포인트
- `POST /api/chat` (SSE Streaming)
- 요청 바디:
  ```json
  {
    "thread_id": "uuid-v4",
    "message": "휴학 절차 어떻게 되나요?",
    "profile": {}
  }
  ```

### 1-2. 이벤트 명세 (SSE Event Types)

| 이벤트명 (`event:`) | 데이터 포맷 (`data:`) | 설명 및 프론트 UI 처리 |
|---|---|---|
| `status` | `{"step": "classify", "msg": "질문 의도 분석 중..."}` | 상단 접이식 'Agent 판단 타임라인'에 실시간 상태 칩 추가 |
| `status` | `{"step": "act", "msg": "학칙 및 학사 규정 검색 중 (3건 발견)..."}` | 도구 호출 진행 상황 실시간 업데이트 |
| `evidence` | `{"items": [{"id": "rule-01", "title": "학칙 제32조(휴학)", "dept": "교무처", "url": "..."}]}` | **답변 생성 전 근거 카드를 선(先)렌더링** (응답 체감 속도 극대화) |
| `interrupt` | `{"missing_slots": ["grade", "has_scholarship"], "question": "학년과 이번 학기 장학금 수혜 여부를 알려주세요."}` | 되묻기 발생 시 대화창에 퀵 선택 칩 또는 입력 모달 노출 |
| `answer` | `{"sentences": [...], "checklist": [...], "next_actions": [...]}` | 검증(verify) 완료된 최종 구조화 답변 본문 렌더링 |
| `done` | `{"turn_id": 1, "completed_at": 1727500000}` | 스트림 종료 및 피드백(👍/👎) 버튼 활성화 |
| `error` | `{"code": 500, "message": "..."}` | 예외 발생 시 안내 문구 표출 |

## 2. 규정 HWP 조문 파싱(Chunking) 엣지 케이스 대응 규칙

경남대 규정관리시스템의 HWP 파일을 텍스트(`hwp5txt`)로 추출할 때 빈번히 발생하는 파싱 실패 및 왜곡을 방지하기 위한 구체적인 전처리 룰입니다.

### 2-1. `article_id` 네임스페이스 분리 (부칙 충돌 방지)
- **문제**: 본문 `제1조(목적)`와 각 개정 차수별 부칙의 `제1조(시행일)`가 동일한 번호를 가져 색인 충돌 및 검색 왜곡 발생.
- **해결 규칙**:
  - 본문: `{규정번호}_main_{조번호}` (예: `20101_main_32`)
  - 부칙: `{규정번호}_add_{개정연월일}_{조번호}` (예: `20101_add_20240301_1`)

### 2-2. 가지번호 및 특수 조문 정규식
- `^제\s*(\d+)조(?:의(\d+))?\s*\(([^)]+)\)`
  - `제12조(수강신청)` → `조=12, 가지=None, 제목=수강신청`
  - `제12조의2(수강철회)` → `조=12, 가지=2, 제목=수강철회`
- 본문이 지나치게 긴 경우: 조(條) 단위 분할 후 2,000자 초과 시 항(①, ②, ③...) 단위 서브 청크 생성

### 2-3. 표(Table) 및 별표/서식 예외 처리
- HWP 내의 복잡한 표(예: 장학금 지급 기준표, 학점 인정 환산표)는 `hwp5txt` 추출 시 텍스트 열 순서가 꼬여 LLM이 오독할 위험이 큼.
- **규칙**:
  - 표가 포함된 조문은 조문 본문 텍스트만 추출하고, 메타데이터에 `has_table: true` 플래그 부여.
  - LLM 프롬프트에 *"세부 기준표는 원문 확인 필요"*를 명시하게 하고, 근거 카드에 `[규정 원문 HWP 다운로드]` 링크를 필수 제공.

## 3. Vertex AI Search ↔ 로컬 하이브리드 검색 전환 "데드라인(Cut-off)"

Vertex AI Search 데이터 스토어 설정, 스키마 매핑(JSONL structData), 색인 반영 지연은 1일차 일정 지연의 가장 큰 리스크입니다.

### 3-1. 전환 판정 데드라인
- **기준 시점**: **1일차(9/29) 18:00 (KST)**
- **체크 조건**:
  1. Vertex AI Search에 업로드한 데이터 스토어가 Active 상태인가?
  2. 테스트 쿼리("휴학 절차", "장학금") 실행 시 관련 조문(Top-3)이 3초 이내 반환되는가?
- 위 조건 불만족 시 즉시 로컬 하이브리드 검색으로 전환.

### 3-2. 로컬 하이브리드 검색 대체 스택
- **키워드(BM25)**: `rank-bm25` (In-Memory 메모리 적재, 규정 조문 수천 개 수준은 20MB 미만)
- **시맨틱(Dense)**: Gemini Embedding API (`text-embedding-004`) + 코사인 유사도 연산
- **하이브리드 결합**: RRF(Reciprocal Rank Fusion) 적용 (`score = 1/(60 + rank_bm25) + 1/(60 + rank_dense)`)
- **보고서 소명 문구**: *"대규모 엔터프라이즈 환경이 아닌 대학 단위 정적 규정의 특성을 고려하여, 외부 클라우드 색인 지연 의존성을 제거하고 경량 독립 하이브리드 검색 엔진(BM25 + Semantic Vector)을 자체 구축하여 응답 속도와 일관성을 확보함."*

## 4. 챗 UI "추천 질문 칩(Quick Replies)" 및 세션 리셋

심사위원 평가 및 3분 시연 영상 녹화 시 입력 실수를 줄이고, 준비된 시나리오가 자연스럽게 동작하도록 돕는 프론트엔드 장치입니다.

### 4-1. 퀵 리플라이 칩 배치 (시작 화면 및 빈 입력창)
- `[휴학 신청 절차 안내]` → 대표 되묻기(ask_user) 및 체크리스트 시연
- `[성적 경고 기준 및 재수강]` → 규정 조문 근거 인용 시연
- `[오늘 학생식당 메뉴]` → 실시간 웹 파싱 도구 시연
- `[학사지원팀 어디 있나요?]` → 담당 부서 위치표 및 지도 도구 시연
- `[기숙사 세탁기 고장 신고]` → 범위 밖(fallback) 및 담당 부서/연락처 안내 시연

### 4-2. 세션 리셋 ("새로운 상담 시작" 버튼)
- `MemorySaver` + 단일 Cloud Run 인스턴스 특성상, 이전 상담에서 입력된 사용자 프로필(예: "2학년, 장학생")이 다음 질문에 오염되지 않도록 우측 상단에 **[새 대화 시작]** 버튼 배치.
- 클릭 시 브라우저 `localStorage`의 `thread_id`를 새로 발급하고 메모리 상태를 초기화.

## 6. 평가 자동화(Eval) 호출 제어 및 비용/Quota 방어

4일차부터 50문항 일괄 평가를 실행할 때 Vertex AI / Gemini API 429(Rate Limit) 방지책입니다.

- **비동기 세마포어 적용**: `asyncio.Semaphore(3)`로 동시 실행 수 상한 제한
- **호출 지연**: 질문 간 300ms 딜레이 부여
- **평가 캐싱**:
  - `eval/cache/` 디렉터리에 `{질문해시}_{모델버전}.json` 형태로 저장
  - 프롬프트나 데이터가 바뀌지 않은 문항은 재호출 없이 기존 채점 결과 재활용
- **지수 백오프**: 429 및 5xx 발생 시 `tenacity` 라이브러리로 최대 5회 재시도 (초기 지연 2초, 지터 적용)
