# 공문 요청 범위 — 초안 (설계 토론 #435~#441)

- 작성: 2026-09-29 (KST) · KNBC-campusBridge-Opus5
- 성격: **교수님 공문 작성 참고자료**. 교수님 #446(2026-09-29): 공문은 교수님이 직접 작성·전달하며, 승인은 확실하므로 개발은 공문 도착을 기다리지 않는다. 아래는 토론에서 정리한 요청 범위로, 참고용으로만 남긴다.
- 원칙: 학교에 요구하는 추가 업무는 **"승인 여부 회신 + 비상 연락 창구"** 로 제한한다(핵심 메시지 "구성원은 하던 일 그대로"와 일치). 변경 감지·재색인·검수는 전부 프로젝트 팀 책임

## 1. 요청 사항 (승인자가 항목별로 예/아니오로 답할 수 있게)

| # | 요청 | 세부 |
|---|---|---|
| 1 | **자동 수집 허용** | 별첨 **허용 대상 목록**(도메인·경로·콘텐츠 유형 HWP/HTML/RSS/PDF·첨부 포함 여부)에 한정. 목록 밖 링크 추적·인증 페이지 제외 |
| 2 | **수집 행위 허용** | 다운로드·텍스트 변환·검색 색인·변경 감지 |
| 3 | **공개 표시 허용**(수집과 분리 승인) | 답변에 규정·안내의 **짧은 인용**, 제목, 원문 링크, **담당 부서 대표 연락처·위치**(팀 단위) 표시 |
| 4 | **교내 문서 인용 범위** | 전지원이 발굴한 기존 교내 문서 중 "챗봇 답변에 인용 가능" 범위 승인(재학생 인증 없이 공개 답변 전제) |
| 5 | **시연용 공개 URL 운영** | 대회 개발·심사 기간 중 공개 데모 운영 |

## 2. 운영 약속 (공문 본문 또는 별첨)

- **식별**: User-Agent `CampusBridge/<버전> (경진대회 시제품; 연락처: <담당자 이메일>)`
- **빈도**: 요청 간격 ≥ 1초. 규정·안내 페이지는 **일 1회 배치**(변경분만). 공지 RSS·학사일정·식단은 **학생 질문 시점 조회 + 캐시**(공지 30분, 일정 24시간, 식단 주 단위) — 캐시로 실제 요청은 게시판별 시간당 최대 약 2회
- **오류 시 자동 중단**: 연속 오류·차단 응답(403·429 등) 시 수집 중단, 담당자 확인 후 재개
- **기간·철회·삭제**: 승인 기간(대회 종료 후 ○일까지 — 교수님 결정), 학교 요청 시 **즉시 수집 중단·색인 삭제**, 사고 연락 창구
- **robots.txt**: 학교가 robots.txt나 서버 설정을 **바꿔 달라고 요청하지 않는다**(학교 업무 증가). **서면 승인을 수집 근거**로 삼을 수 있는지만 확인 요청
- **고지**: 화면에 "대회 시제품 — 학교 공식 서비스 아님, 최종 확인은 원문" 표시. 학교 로고·상표는 사용하지 않음(필요 시 별도 요청)

## 3. 요청하지 않는 것

- 로그인 우회, 학생정보시스템·e-Class 접근, 비공개 문서의 새 제공
- 장학 Q&A·개인 상담 기록 제공
- 직원 개인 이름·개인 연락처의 수집·표시
- 학교 측의 데이터 가공·정리·API 제공, robots.txt·방화벽 설정 변경
- 정확성 보증, 변경 사항 개별 통보
- **수집 서버 IP 사전 등록(방화벽 예외)** — 전산팀 업무를 늘리는 요청이라 기본 공문에서 제외(#440·#441). **조건부 후속안**: 실제 차단이 발생하고 학교가 IP 허용 방식만 지원한다고 회신하면, 고정 발신 IP(Cloud NAT·예약 IP — 비용 발생)를 교수님 승인 후 구성해 **확정된 단일 IP만** 전달
